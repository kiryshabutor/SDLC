# Дополнительные спецификации

Для веб-сервиса «Охотник за скидками в Steam», релиз R1

Подготовил Бутор К. П., гр. 450503 · Версия 1.0 · 08.11.2026

## 1. Назначение

Модель прецедентов (`docs/use-case-model.md`) описывает функциональное поведение Системы: что делает каждый актёр и как Система отвечает. Требования, которые не относятся к одному прецеденту, а действуют для всей Системы (производительность, надёжность, безопасность, ограничения среды и внешних сервисов), собраны в этом документе. Они не дублируют SRS, а группируют её требования вокруг модели прецедентов и показывают, на какие прецеденты каждое требование влияет.

Источник требований: SRS v0.4 (`srs/srs.md`, разделы 2.3, 2.5, 3.3–3.5). Термины: [glossary.md](glossary.md).

## 2. Функциональность, общая для всех прецедентов

| ID | Спецификация | Требования SRS | Прецеденты |
|----|--------------|----------------|------------|
| SS-01 | Все действия пользователя, кроме UC-01…UC-03 и отписки по ссылке из письма, выполняются только в рамках действующей сессии. Чужие данные недоступны: запрос возвращает 404 | REQ-SEC-003, REQ-SEC-004 | UC-04…UC-15 |
| SS-02 | Все входные данные проверяются на сервере. Ошибка возвращается в едином формате `{"error": {"code", "message", "field"}}` и показывается пользователю на русском языке | REQ-SEC-009, REQ-INT-011 | все |
| SS-03 | Все цены показываются в валюте региона пользователя без конвертации, в том виде, в котором их возвращает Steam | REQ-FUNC-005, A-8 | UC-04, UC-08, UC-09, UC-13 |
| SS-04 | Каждое значимое действие и каждый цикл опроса записываются в журнал JSON с идентификатором запроса или цикла | REQ-OBS-001, REQ-OBS-002 | все |

|----|--------------|----------------|

| SS-18 | Обмен с браузером только по HTTPS; cookie сессии `HttpOnly`, `Secure`, `SameSite=Lax`; изменяющие запросы защищены от CSRF | REQ-SEC-002, REQ-SEC-003, REQ-SEC-009 |

| SS-20 | Хранятся только email, хэш пароля, регион, настройки уведомлений, ссылка на профиль Steam, SteamID64 и chat_id Telegram. Удаление учётной записи удаляет все персональные данные | REQ-SEC-010, REQ-FUNC-007, REQ-COMP-001 |

## 9. Связь с моделью

Каждая спецификация из разделов 2–7 привязана к прецедентам, на которые она влияет. При изменении прецедента в `docs/use-case-model.md` проверяются связанные спецификации, а при изменении спецификации обновляются альтернативные и ошибочные потоки затронутых прецедентов. Правила ведения модели описаны в ADR-0010.
