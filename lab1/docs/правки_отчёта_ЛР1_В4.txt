2 КРАТКИЕ ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ

Исправить заголовок: «СВЕДЕНИЕ» → «СВЕДЕНИЯ». Полностью заменить подпункты 2.1–2.5.

2.1 Интегрированная среда разработки и её компоненты

Интегрированная среда разработки (IDE, Integrated Development Environment) представляет собой единую рабочую среду программиста. Она объединяет редактор исходного кода с подсветкой синтаксиса, средства управления проектом и сборки, отладчик, инструменты тестирования и расширения.

Visual Studio Code — кроссплатформенная среда разработки, применяемая в работе вместе с расширением Go. В ней используются проводник Explorer для просмотра файлов, редактор кода, панели Problems и Output, встроенный терминал, средства Run and Debug и каталог расширений. Графический интерфейс приложения Fyne создаётся программно, поэтому визуальный конструктор форм не требуется.

2.2 Основные приёмы работы с редактором кода

Расширение Go использует языковой сервер gopls: он показывает диагностические сообщения, предлагает автодополнение и быстрые исправления. В Visual Studio Code на Ubuntu автодополнение вызывается сочетанием Ctrl+Space, быстрые исправления — Ctrl+., форматирование документа — Shift+Alt+F. Клавиша F12 переходит к определению символа, Shift+F12 показывает его использования, а F2 выполняет безопасное переименование.

2.3 Сборка, запуск и отладка Go-приложения

Зависимости проекта описаны в файлах go.mod и go.sum. В Ubuntu перед первым запуском Fyne устанавливаются системные библиотеки командой sudo apt install gcc libgl1-mesa-dev xorg-dev. Команда go mod tidy синхронизирует зависимости, go build ./... компилирует пакеты, go run ./cmd/weight-calculator запускает приложение, а go test ./... выполняет тесты. В Visual Studio Code запуск и отладка выполняются клавишей F5 через расширение Go и отладчик Delve; точка останова устанавливается щелчком слева от номера строки или клавишей F9. При остановке доступны значения переменных и стек вызовов; F10, F11 и Shift+F11 выполняют соответственно шаг с обходом, шаг с входом и выход из функции.

2.4 Паттерн MVC

Паттерн MVC (Model–View–Controller) разделяет приложение на три компонента. Модель хранит состояние и предметные данные, представление формирует интерфейс и отображает состояние, контроллер принимает действия пользователя и передаёт команды прикладной логике. В проекте расчёт вынесен в отдельный сервис, что позволяет проверять его независимо от графического интерфейса Fyne.

2.5 Активная и пассивная модель

Паттерн MVC предполагает два способа обновления данных. В пассивной модели контроллер эксклюзивно управляет моделью: он вносит изменения, а затем напрямую сообщает представлению о необходимости обновления. Активная модель опирается на паттерн «Наблюдатель» (Observer): модель самостоятельно рассылает уведомления при смене своего состояния. Представление подписывается на эти оповещения и само запрашивает актуальные данные, тогда как контроллер лишь обрабатывает действия пользователя. В данной лабораторной работе активная модель реализована посредством уведомления ModelUpdated модели WeightModel.

3 ОПИСАНИЕ ВЫПОЛНЕННОГО ВАРИАНТА ЗАДАНИЯ

3.1 Постановка задачи

Вариант 4 требует разработать программу «Калькулятор веса на разных планетах». Пользователь вводит вес человека на Земле. Программа рассчитывает и отображает вес на Меркурии, Венере, Земле, Марсе, Юпитере, Сатурне, Уране и Нептуне с учётом относительной силы тяжести. Ввод выполняется в отдельном окне по кнопке «Ввести данные»; последние корректные данные восстанавливаются при повторном открытии окна, а ошибки сопровождаются сообщением.

Среда разработки – Visual Studio Code, язык – Go 1.23, графическая библиотека – Fyne v2.6.3, операционная система – Ubuntu.

3.2 Настройка среды и расширений для UML и SysML v2

Установлена среда Visual Studio Code. Создан Go-модуль с именем lab1; в файле go.mod указана целевая версия Go 1.23. Для запуска графического приложения Fyne в Ubuntu установлены системные зависимости командой sudo apt install gcc libgl1-mesa-dev xorg-dev.

Для разработки и отладки используется расширение Go. Для работы с UML установлено расширение PlantUML; диаграмма приложения хранится в файле docs/architecture.puml и экспортируется в PNG или SVG. Для текстового описания структуры используется нотация, близкая к SysML v2.

3.3 Демонстрация отладчика

Работа отладчика продемонстрирована в методе Calculate структуры Calculator в файле internal/service/calculator.go. Точка останова устанавливается перед преобразованием введённой строки в число с помощью strconv.ParseFloat. При остановке в панели Variables видны исходная строка rawWeight, нормализованная строка value и рассчитанное число weight. Пошаговое выполнение позволяет проконтролировать проверку допустимости введённых данных, обход списка планет, формирование PlanetWeight и вызов метода SetState активной модели.

3.4 Структура проекта и каркас MVC с активной моделью

Проект разделён на пакеты, соответствующие компонентам MVC:

– model: активная модель WeightModel, структуры Planet, PlanetWeight и State для хранения состояния приложения;
– service: Calculator, выполняющий проверку введённого веса и расчёт значений для планет;
– controller: WeightController, связывающий действие пользователя и сервис;
– view: представления MainWindow и окно ввода веса, созданные средствами Fyne;
– cmd/weight-calculator: точка входа приложения.

В main.go создаются модель, калькулятор и контроллер, после чего вызывается view.Run. Главное окно подписывается на модель. Представление передаёт введённую строку контроллеру, контроллер вызывает Calculator. После успешной проверки Calculator формирует новое состояние и передаёт его модели. WeightModel сохраняет состояние и уведомляет представление методом ModelUpdated, после чего на главной форме обновляются результаты.

Рисунок 3.3 – Диаграмма типов и интерфейсов приложения

3.5 Модель

WeightModel хранит State, содержащий признак наличия введённого значения HasValue, вес на Земле EarthWeight и список результатов PlanetWeight. Модель также хранит срез observers. Метод SetState сохраняет копию нового состояния и уведомляет подписчиков вызовом ModelUpdated. Метод State возвращает копию текущего состояния, поэтому представление не изменяет внутренние данные модели напрямую.

Функция Planets возвращает список планет и коэффициенты силы тяжести относительно Земли. Структура PlanetWeight объединяет планету и рассчитанный для неё вес. Модель не зависит от Fyne, поэтому её состояние и расчёты могут проверяться средствами тестирования Go.

3.6 Представление

MainWindow создаёт главное окно Fyne с заголовком «Калькулятор веса на планетах», кнопкой «Ввести данные», меткой веса на Земле и списком результатов. MainWindow реализует интерфейс Observer. Метод ModelUpdated получает новое State, форматирует значения с точностью до двух знаков и обновляет метки результатов.

Окно ввода создаётся функцией newInputWindow. Оно содержит поле веса и кнопки «Рассчитать» и «Отмена». Если модель уже содержит корректное значение, оно подставляется в поле ввода перед показом окна. Представление передаёт контроллеру исходную строку и не выполняет расчёт самостоятельно. При ошибке используется диалог Fyne dialog.ShowError.

3.7 Контроллер

WeightController связывает пользовательский интерфейс и прикладную логику. Метод Calculate принимает строку из формы и передаёт её объекту Calculator. Метод CurrentState позволяет получить сохранённое состояние через сервис. Контроллер не содержит алгоритма расчёта веса и не зависит от конкретных виджетов Fyne.

Calculator удаляет внешние пробелы, заменяет запятую на точку и преобразует строку функцией strconv.ParseFloat. Вес должен быть положительным конечным числом. Если введена пустая строка, текст, ноль, отрицательное значение, бесконечность или NaN, возвращается ошибка «введите положительное число, например 70». Окно ввода выводит это сообщение пользователю и не закрывается.

3.8 Запоминание данных и обработка ошибок

Запоминание реализуется за счёт хранения структуры State внутри модели WeightModel. После успешного расчёта State содержит последний вес на Земле. При открытии окна ввода проверяется поле HasValue; если оно истинно, функция formatWeight преобразует сохранённое значение в строку и подставляет его в поле.

Обработка ошибок выполняется до изменения модели. Сначала Calculator нормализует строку и преобразует её в число. Затем проверяются положительность и конечность полученного значения. При обнаружении ошибки новое состояние не устанавливается, поэтому предыдущие корректные данные и результаты сохраняются. Сообщение отображается в окне с помощью dialog.ShowError.

5 ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

Вопрос 1 Какие компоненты входят в состав IDE?

В состав IDE входят редактор кода, компилятор или интерпретатор, система сборки, отладчик, средства запуска, навигация и рефакторинг, интеграция с системой контроля версий, терминал и расширения. В Visual Studio Code эти функции представлены Explorer, Search, Source Control, Run and Debug, Extensions, Problems, Output и Terminal; языковые функции Go предоставляет gopls.

Вопрос 2 Каковы основные приёмы работы с редактором кода?

Основные приёмы включают автодополнение, быстрые исправления, переименование, поиск определений и ссылок, форматирование gofmt, организацию импортов, сворачивание блоков и сравнение версий Git. gopls выполняет фоновую диагностику и отмечает часть ошибок до сборки.

Вопрос 3 Каким образом выполняется сборка и запуск проекта?

Команда go build ./... компилирует пакеты модуля, go run ./cmd/weight-calculator собирает и запускает приложение, go test ./... выполняет тесты. Эти команды запускаются во встроенном терминале Visual Studio Code. Конфигурация Go в launch.json передаёт запуск отладчику Delve.

Вопрос 4 Что такое MVC?

MVC – архитектурный паттерн, разделяющий данные и бизнес-логику, графический интерфейс и обработку действий пользователя. Model хранит состояние приложения. View отображает данные и принимает действия пользователя. Controller передаёт действие сервису. В работе этими ролями служат WeightModel, MainWindow с окном ввода Fyne и WeightController; вычисления выполняет Calculator.

Вопрос 5 Чем отличается активная модель от пассивной?

Пассивная модель не уведомляет представление: после изменения данных Controller отдельно инициирует обновление View. Активная модель реализует подписку и после изменения сама вызывает наблюдателей. В работе WeightModel хранит срез Observer и вызывает ModelUpdated, а MainWindow обновляет метки из полученного State.
