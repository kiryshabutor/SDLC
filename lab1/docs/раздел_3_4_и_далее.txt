3.4 Структура проекта и каркас MVC с активной моделью

Проект разделён на пакеты, соответствующие компонентам MVC:
– model: активная модель WeightModel, структуры Planet, PlanetWeight и State;
– view: представление MainWindow с главным окном и окном ввода веса;
– controller: контроллер WeightController, связывающий представление и сервис;
– service: сервис Calculator для проверки и расчёта;
– cmd/weight-calculator: точка входа приложения.

В main.go создаются модель, сервис, контроллер и представление, после чего запускается приложение Fyne. Представление передаёт введённое значение контроллеру, который вызывает сервис. После успешного расчёта сервис изменяет состояние модели, а активная модель уведомляет представление методом ModelUpdated. В результате на главной форме обновляются данные о весе на планетах.

3.5 Модель

Модель реализована в пакете internal/model. Структура Planet содержит название планеты и коэффициент силы тяжести, PlanetWeight — планету и рассчитанный вес, а State — исходный вес и результаты расчёта. WeightModel хранит состояние и список наблюдателей: метод Subscribe добавляет представление, а SetState сохраняет новое состояние и вызывает ModelUpdated у всех подписчиков. Функция Planets задаёт коэффициенты для восьми планет. Модель не зависит от Fyne, поэтому логику хранения и расчёта можно проверять отдельными тестами Go.

3.6 Представление

Представление реализовано в пакете internal/view структурой MainWindow. Главное окно содержит кнопку ввода, метку веса на Земле и область вывода результатов. Приложение создаётся с постоянным идентификатором, поэтому настройки Fyne доступны после повторного запуска. При создании главного окна из настроек считывается последний корректный вес; при наличии значения оно подставляется в поле при открытии формы ввода. После подтверждения исходная строка передаётся контроллеру, а ошибка выводится диалогом Fyne. MainWindow реализует интерфейс Observer: метод ModelUpdated обновляет метку и список рассчитанных значений. Представление не выполняет расчёт и проверку данных.

3.7 Контроллер

Контроллер WeightController из пакета internal/controller хранит ссылку на Calculator и предоставляет методы Calculate и CurrentState. Метод Calculate получает строку из формы и передаёт её сервису, который проверяет значение, рассчитывает вес и изменяет состояние модели. При ошибке она возвращается в представление для вывода пользователю. После успешного расчёта представление получает текущий результат методом CurrentState и сохраняет вес в настройках Fyne. Таким образом, контроллер принимает действие пользователя и вызывает бизнес-логику.

3.8 Запоминание данных и обработка ошибок

После успешной проверки и расчёта вес на Земле сохраняется в State модели и в настройках Fyne методом SetFloat. При следующем запуске приложения значение считывается методом FloatWithFallback и подставляется в поле ввода. Обработка ошибок выполняется сервисом Calculator до изменения модели и сохранения настроек. Проверяются пустая строка, отрицательное или нулевое значение, буквы, несколько десятичных разделителей, невозможность преобразования, NaN и бесконечность. Запятая допускается как десятичный разделитель и заменяется на точку перед преобразованием в число. При ошибке SetState не вызывается, поэтому предыдущие результаты и сохранённое значение не изменяются. При корректном вводе для каждой планеты применяется формула Wпланеты = WЗемли × Gпланеты, а новые данные передаются модели и отображаются в окне.

5 ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

Вопрос 1 Какие компоненты входят в состав IDE?

В состав IDE входят редактор кода, компилятор или интерпретатор, система сборки, отладчик, средства запуска, навигация и рефакторинг, интеграция с системой контроля версий, терминал и расширения. В Visual Studio Code эти функции представлены Explorer, Search, Source Control, Run and Debug, Extensions, Problems и Terminal; языковые функции Go предоставляет gopls.

Вопрос 2 Каковы основные приёмы работы с редактором кода?

Основные приёмы включают автодополнение, быстрые исправления, переименование, поиск определений и ссылок, форматирование gofmt, организацию импортов, сворачивание блоков и сравнение версий Git. Расширение Go выполняет фоновую диагностику и отмечает часть ошибок до сборки.

Вопрос 3 Каким образом выполняется сборка и запуск проекта?

Команда go build ./... компилирует пакеты модуля, go run ./cmd/weight-calculator собирает и запускает приложение, go test ./... выполняет тесты. Эти команды запускаются в терминале Visual Studio Code. Для пошагочной отладки используется расширение Go и отладчик Delve.

Вопрос 4 Что такое MVC?

MVC — архитектурный паттерн, разделяющий данные и бизнес-логику, графический интерфейс и обработку действий пользователя. Model хранит состояние и выполняет расчёт, View отображает данные, Controller принимает действие пользователя и передаёт его бизнес-логике. В работе этими ролями служат WeightModel, MainWindow и WeightController.

Вопрос 5 Чем отличается активная модель от пассивной?

Пассивная модель не уведомляет представление: после изменения данных контроллер отдельно инициирует обновление View. Активная модель реализует подписку и после изменения сама вызывает наблюдателей. В работе WeightModel хранит список Observer и вызывает ModelUpdated, а MainWindow получает новое состояние и обновляет элементы интерфейса.

В ходе лабораторной работы изучены основные компоненты Visual Studio Code, расширение Go, форматирование gofmt, сборка, тестирование и отладка с Delve. Для представления архитектуры приложения подготовлена диаграмма типов и интерфейсов.

Разработана программа расчёта веса человека на планетах Солнечной системы на языке Go с интерфейсом Fyne. Она принимает вес на Земле и отображает рассчитанные значения для восьми планет. Последнее корректное значение сохраняется в настройках Fyne и подставляется при повторном открытии окна ввода, в том числе после перезапуска приложения; пустые, нечисловые, нулевые и отрицательные значения сопровождаются сообщениями об ошибке. WeightModel хранит состояние и уведомляет MainWindow, а WeightController передаёт действия пользователя сервису расчёта.
