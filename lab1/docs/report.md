## 1. Цель работы

Изучить возможности интегрированной среды разработки, научиться создавать приложение с графическим интерфейсом, использовать средства отладки и реализовать архитектуру MVC с активной моделью.

## 2. Постановка задачи

По варианту 4 необходимо разработать калькулятор веса на разных планетах. Пользователь вводит свой вес на Земле. Программа рассчитывает вес на планетах Солнечной системы и отображает результаты на главной форме.

Программа должна:

- иметь кнопку «Ввести данные» на главной форме;
- открывать отдельное окно для ввода веса;
- запоминать последние введённые данные и подставлять их при повторном вводе;
- выводить рассчитанные значения на главной форме;
- показывать сообщение об ошибке при некорректном вводе;
- использовать MVC с активной моделью.

## 3. Используемые средства

- Go 1.23;

Установка зависимостей проекта и запуск выполняются командами:

Проверка тестов:

    go test ./...

## 4. Описание алгоритма

Вес на планете вычисляется по формуле:

    Wпланеты = WЗемли × Gпланеты

где Gпланеты — коэффициент силы тяжести относительно Земли.

| Планета | Коэффициент | Пример для 70 кг |
|---|---:|---:|
| Меркурий | 0,38 | 26,60 кг |
| Венера | 0,91 | 63,70 кг |
| Земля | 1,00 | 70,00 кг |
| Марс | 0,38 | 26,60 кг |
| Юпитер | 2,36 | 165,20 кг |
| Сатурн | 0,92 | 64,40 кг |
| Уран | 0,89 | 62,30 кг |
| Нептун | 1,12 | 78,40 кг |

Ввод очищается от пробелов, запятая заменяется на точку, после чего строка преобразуется в число. Нулевые, отрицательные, бесконечные и нечисловые значения отклоняются.

## 5. Архитектура приложения

В проекте использована слоистая реализация MVC:

    View → Controller → Service → Model

### Model

Пакет internal/model содержит структуры Planet, PlanetWeight, State и класс WeightModel. Модель хранит текущий введённый вес и рассчитанные значения. Представление подписывается на модель через интерфейс Observer.

### View

Пакет internal/view содержит главное окно MainWindow и отдельное окно ввода. MainWindow отображает данные и реализует метод ModelUpdated. После изменения состояния модель сама уведомляет представление, поэтому модель является активной.

### Controller

Пакет internal/controller содержит WeightController. Контроллер принимает действие пользователя и передаёт введённую строку сервису.

### Service

Пакет internal/service содержит Calculator. Сервис выполняет проверку ввода, вычисляет вес на каждой планете и записывает новый State в модель.

### Точка входа

Файл cmd/weight-calculator/main.go создаёт модель, сервис, контроллер и представление, после чего запускает главное окно.

## 7. Работа программы

1. После запуска открывается главное окно «Калькулятор веса на планетах».
2. Нажатие кнопки «Ввести данные» открывает дополнительное окно.
3. Пользователь вводит вес на Земле, например 70 или 70,5.
4. После нажатия «Рассчитать» главное окно показывает вес на всех планетах.
5. При повторном открытии окна последнее значение уже находится в поле ввода.
6. При вводе строки abc, нуля или отрицательного числа отображается сообщение об ошибке, а предыдущие результаты не изменяются.

## 9. Ответы на контрольные вопросы

### 1. Какие компоненты входят в состав IDE?

Основными компонентами IDE являются редактор исходного кода, средства управления проектом, компилятор или система сборки, запуск приложения, отладчик, инструменты тестирования, интеграция с системой контроля версий, встроенный терминал и система расширений.

### 2. Каковы основные приёмы работы с редактором кода?

К основным приёмам относятся ввод и редактирование текста, автоматическое форматирование, автодополнение, переход к определению символа, поиск и замена, переименование с учётом ссылок, работа с несколькими файлами и использование горячих клавиш.

### 3. Каким образом выполняется сборка и запуск проекта?

Для Go зависимости описываются в go.mod. Команда go build ./... компилирует проект, go run ./cmd/weight-calculator компилирует и запускает приложение, а go test ./... запускает тесты всех пакетов.

### 4. Что такое MVC?

MVC — архитектурный шаблон, разделяющий приложение на Model, View и Controller. Model хранит данные и бизнес-состояние, View отображает состояние и принимает действия пользователя, Controller обрабатывает действия и связывает View с Model.

### 5. Чем отличается активная модель от пассивной?

В активной модели после изменения данных модель сама уведомляет подписанные представления, и они обновляются автоматически. В пассивной модели модель только хранит данные, а контроллер должен явно сообщить представлению о необходимости обновления.
