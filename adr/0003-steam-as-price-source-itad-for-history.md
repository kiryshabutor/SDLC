# Steam — источник текущих цен, IsThereAnyDeal — только история для US и PL

## Контекст и постановка задачи

Системе нужны текущие цены по пяти регионам (BY, RU, KZ, US, PL) и прошлая история цен, чтобы график и условие «исторический минимум» были полезны с первого дня. Проверка API (SRS, Приложение В) показала, что IsThereAnyDeal отдаёт корректные цены только для US и PL, а для BY, RU, KZ молча возвращает цены США. Steam Store API отдаёт цены всех регионов, но не хранит историю.

Откуда брать текущие цены и откуда историю, чтобы не показать пользователю чужие цены?

## Драйверы решения

* Цены в регионе пользователя должны совпадать с ценами на странице Steam (REQ-INT-006).
* История региона не должна смешиваться с данными другого региона (A-5).
* Внешние сервисы должны быть бесплатными (REQ-COST-001).
* Система должна работать без ITAD (REQ-REL-004).
* Условия использования ITAD: атрибуция, неизменность данных (REQ-COMP-002).

## Рассмотренные варианты

* Только Steam, история накапливается с нуля
* Только ITAD для текущих цен и истории
* Steam для текущих цен, ITAD для истории US и PL и для дат мировых распродаж
* Парсинг SteamDB

## Итог решения

Выбранный вариант: «Steam для текущих цен, ITAD для истории US и PL и для дат мировых распродаж», потому что только он даёт правильные цены во всех регионах и непустой график хотя бы для части регионов.

### Последствия

* Хорошо, потому что цены BY, RU, KZ всегда берутся из первоисточника.
* Хорошо, потому что для BY, RU, KZ пользователь видит блок «Скидки в мире» с датами и процентами, без чужих цен (REQ-FUNC-024).
* Плохо, потому что для BY, RU, KZ график в первые недели почти пустой. Это отражено пометкой «История неполная» (REQ-FUNC-023).
* Плохо, потому что эндпоинты Steam не документированы Valve и могут измениться (A-1). Риск снижен интерфейсом `PriceSource` (DV-006).
* Нейтрально, потому что записи истории хранят поле `source` (`steam`, `itad`, `test`), и на графике участки ITAD выделяются.

### Подтверждение

Интеграционный тест для Elden Ring проверяет, что в регионе BY в `price_history` нет записей с `source = 'itad'`. Код-ревью проверяет, что `HistorySource.History` возвращает `ErrRegionUnsupported` для регионов с `itad_supported = false`.

## Плюсы и минусы вариантов

### Только Steam

* Хорошо, потому что один источник и нет зависимости от ITAD.
* Плохо, потому что график и исторический минимум бесполезны первые месяцы во всех регионах.

### Только ITAD

* Хорошо, потому что история и текущие цены из одного API.
* Плохо, потому что для BY, RU, KZ цены неверные: это ключевые регионы целевой аудитории.

### Steam + ITAD для US/PL

* Хорошо, потому что правильные цены везде, история там, где она достоверна.
* Нейтрально, потому что два клиента API и два лимита запросов.

### Парсинг SteamDB

* Плохо, потому что публичного API нет, парсинг запрещён условиями сайта, а регион BY SteamDB не отслеживает.

## Дополнительная информация

Связанные требования: REQ-INT-006, REQ-INT-009, REQ-FUNC-017…019, REQ-FUNC-023, REQ-FUNC-024, REQ-REL-004, REQ-COMP-002, допущения A-1, A-5, A-6. Элементы SDD: DV-006, DV-010. Решение пересматривается, если ITAD начнёт поддерживать регионы BY, RU, KZ.
