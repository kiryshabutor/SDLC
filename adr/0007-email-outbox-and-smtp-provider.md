# Отправка писем через outbox; Gmail SMTP в эксплуатации, Mailpit в тестовом режиме

## Контекст и постановка задачи

Система отправляет письма подтверждения, сброса пароля и дайджесты уведомлений. SMTP-сервер может быть временно недоступен, а письмо должно уйти после восстановления (REQ-REL-005). SRS оставил открытым выбор почтового провайдера (Приложение Д, вопрос 2), при этом он должен быть бесплатным (REQ-COST-001). Для демонстрации письма должны приходить за минуту и без реального ящика (REQ-FUNC-030).

Как организовать отправку писем и какой SMTP-сервер использовать?

## Драйверы решения

* Письмо не теряется при сбое SMTP и при перезапуске процесса.
* Регистрация не зависит от доступности SMTP.
* Бесплатный провайдер с объёмом, достаточным для учебной эксплуатации (A-7).
* Смена провайдера без изменения кода (REQ-INT-010).
* Наглядная демонстрация писем на защите.

## Рассмотренные варианты

* Таблица `email_outbox` + отправка обработчиком; Gmail SMTP с паролем приложения; Mailpit в тестовом режиме
* Синхронная отправка из обработчика HTTP-запроса
* Транзакционный сервис рассылок с HTTP API (бесплатный тариф)

## Итог решения

Выбранный вариант: «Outbox + Gmail SMTP + Mailpit», потому что outbox даёт гарантированную доставку с повторами без брокера сообщений, Gmail бесплатен и работает по стандартному SMTP, а Mailpit показывает все письма в веб-интерфейсе на демонстрации.

### Последствия

* Хорошо, потому что письмо создаётся в той же транзакции, что и событие, и не может потеряться.
* Хорошо, потому что провайдер меняется переменными `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`.
* Плохо, потому что Gmail ограничивает отправку примерно 500 письмами в сутки. Для учебной эксплуатации этого достаточно, а дайджесты сокращают число писем до одного на пользователя за цикл.
* Плохо, потому что письма уходят с задержкой до 10 с (период опроса outbox). Это укладывается в REQ-PERF-005.
* Нейтрально, потому что отправка скрыта за интерфейсом `Notifier`, и в R2 к нему добавится Telegram.

### Подтверждение

Тест REQ-REL-005: при недоступном SMTP уведомление появляется на сайте, письмо остаётся в `pending` и уходит после восстановления. Демонстрация REQ-FUNC-030: письмо видно в веб-интерфейсе Mailpit не позже чем через минуту после изменения цены.

## Плюсы и минусы вариантов

### Outbox + Gmail + Mailpit

* Хорошо, потому что надёжность и бесплатность.
* Нейтрально, потому что нужен пароль приложения Google и включённая двухфакторная аутентификация на почтовом ящике проекта.

### Синхронная отправка

* Хорошо, потому что проще всего.
* Плохо, потому что регистрация падает при сбое SMTP, а письмо теряется при перезапуске.

### Сервис рассылок с HTTP API

* Хорошо, потому что статистика доставки и высокие лимиты.
* Плохо, потому что привязка к API конкретного сервиса и требование подтвердить домен отправителя, которого у учебного проекта нет.

## Дополнительная информация

Закрывает открытый вопрос 2 SRS. Связанные требования: REQ-FUNC-002, REQ-FUNC-004, REQ-FUNC-027, REQ-INT-010, REQ-REL-005, REQ-COST-001. Элементы SDD: DV-008, DV-013.
